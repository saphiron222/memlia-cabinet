# Distribution du frontend Memlia

Le frontend combine directement des composants Plane et Propel sous **AGPL-3.0-only**, des primitives Twenty et des composants cal.diy sous MIT, des tableaux applicatifs Twenty sous AGPLv3 avec leur permission additionnelle originale, et le code Memlia qui les intègre. Le frontend combiné et le code propre qui en constitue les adaptations sont distribués sous AGPL-3.0-only. Les licences et droits d'auteur des composants MIT, des polices OFL et des autres dépendances restent conservés ; ils ne deviennent pas des composants MIT par intégration.

Le périmètre concret comprend `apps/web` et les parties de `packages/contracts` et `packages/ui` intégrées dans le bundle frontend. La mise à disposition du code propre dans cette œuvre sous AGPL ne retire pas les licences permissives des composants tiers. Le backend métier `apps/server`, qui fonctionne comme un processus HTTP séparé avec ses propres données, commandes, droits et contrats, n'est pas relabellisé par cette modification. Aucune conclusion de licence globale sur le backend n'est déduite du seul port de composants.

Le texte AGPL intégral est fourni dans `apps/web/LICENSE` et dans `apps/web/src/upstream/plane/LICENSE`. Les fichiers adaptés conservent les mentions Plane. La provenance fichier par fichier, les révisions exactes, les empreintes original/adapté et les adaptations sont dans `docs/design-interface-provenance.json`. La provenance Twenty et ses 59 empreintes conservées restent dans `packages/ui/PROVENANCE.json`. La licence cal.diy d'origine est fournie dans `apps/web/src/upstream/cal/LICENSE`. Les licences des polices sont sous `apps/web/public/fonts`.

Chaque construction distribue `/licenses/source.tar.gz`, une archive du **source correspondant à cette construction** : frontend et composants intégrés, sources modifiées, styles, polices, verrou exact, scripts et configuration de compilation. Le paquet Propel exact et ses sources originales contenues dans les source maps sont également joints. `/licenses/source-build.json` identifie l'archive par SHA-256 ; son manifeste interne donne les empreintes de chaque fichier. L'accès « Code source · licences » est visible dans la navigation et dans l’en-tête lorsqu’elle est repliée. Les sources et licences restent servies sans compte applicatif. L'hébergeur doit conserver cet accès pour les utilisateurs du frontend, y compris par réseau, et fournir les sources correspondant à ses propres modifications déployées.

Reconstruction : Node >=22.22, `npm ci --ignore-scripts`, puis `npm run build --workspace @memlia/web`. L'archive garde le manifeste du workspace serveur pour la résolution d'origine, mais n'embarque pas son implémentation. Le frontend communique avec l'API canonique `/api/v1`. Les fichiers privés, données, comptes, captures, secrets et preuves de travail ne sont jamais inclus. Les notices des dépendances de production sont distribuées sous `/licenses/` avec leur index.

Ce candidat reste local jusqu'à la revue et aux contrôles de publication. Aucun élément professionnel ou non communautaire Plane/cal/Twenty n'est repris. Les stores, comptes, services, fonctions de publication et backends amont ne sont pas importés.

Les sources Propel récupérées sont modifiables avec [l’adaptateur Vite fourni](propel-source-rebuild.md). La reconstruction frontend avec le paquet verrouillé et la compilation des modules Propel récupérés sont deux preuves distinctes. Le second chemin conserve les barrels/CSS/assets publiés et ne reconstitue pas la chaîne tsdown/génération amont absente du tarball ; ces limites factuelles restent proposées à la revue de distribution, sans affirmation de conformité juridique totale.
