## INPI

**Faits communs.** Base production `https://registre-national-entreprises.inpi.fr/api`, test publié `https://registre-national-entreprises-pprod.inpi.fr/api`. `POST /sso/login`, JSON `{username,password}`, retourne `token` et `user` ; appels suivants `Authorization: Bearer <token>`. Durée/refresh non documentés. Confidentialité soumise aux habilitations. Pour `deleted:true`, la documentation demande le retrait du document déjà téléchargé. Codes : 400 requête, 401 authentification, 403 habilitation, 429 quota quotidien, 500 panne ; actes/comptes annoncent 10 000 appels API/IHM ou 10 000 Mo/jour. [Actes v4, §§A–B/F, pp.3–4/9](https://www.inpi.fr/sites/default/files/2025-06/documentation%20technique%20API%20Actes%20v4.0.pdf).

La [page officielle actuelle](https://data.inpi.fr/content/editorial/Acces_API_Entreprises) lie toujours formalités **v5 août 2026**, actes **v4 juin 2025**, comptes fichier **v6-1 septembre 2026**. Comptes affiche pourtant **v6.0** en couverture et « version 6 » dans l’historique : conserver cette divergence. [PDF comptes, pp.1/44](https://www.inpi.fr/sites/default/files/2026-09/documentation%20technique%20API_comptes_annuels%20v6-1-AA.pdf). Couverture annoncée : comptes commerciaux depuis janvier 2017, actes commerciaux depuis 1993 ; actualisation quotidienne pour ces jeux et CMC. Aucun accès aux brouillons privés du Guichet unique n’en découle.

## Pennylane dossiers

**Faits du guide OAuth général, explicitement destiné aussi aux jetons Firm (10/06/2026, sans version API indiquée).** Authorization Code, application préalablement accordée : base `https://app.pennylane.com`, `GET /oauth/authorize` (`client_id,redirect_uri,response_type=code,scope,state`), `POST /oauth/token` formulaire (`client_id,client_secret,code,redirect_uri,grant_type=authorization_code`). Réponse `access_token,token_type,expires_in=86400,refresh_token`. Refresh `POST /oauth/token`, `grant_type=refresh_token`, `client_id,client_secret,refresh_token` : rotation immédiate invalidant anciens access/refresh ; refresh valable 90 jours. Visibilité dépend de l’utilisateur accordant l’accès, dont sociétés confidentielles. [Guide OAuth, étapes 1–4](https://pennylane.readme.io/docs/oauth-20-walkthrough).

## Pilotes locaux proposés, limites de recette

**Propositions :** cinq adaptateurs configurés en lecture seule réalisables localement : HTTP local pour INPI/Firm ; faux pilote SQL pour fiscal. Ce dernier éprouve requêtes/types/parser, pas le transport ClickHouse réel. Aucun pilote Redshift déduit d’un formulaire tiers.

Fixtures fictives à construire : CMC création puis modification, deux pages, arrêt/rejeu du curseur ; actes liste/détail/PDF interrompu puis reprise, tombstone ; comptes deux exercices et versions, JSON confidentiel sans détail/PDF refusé ; Firm deux pages puis retrait de visibilité et refresh concurrent refusé ; fiscal deux entrepôts, lots SQL interrompus, dates identiques et TVA sans document/date source. Tous : mauvaise identité,401/403/429/500 ou refus SQL, schéma inconnu, binaire tronqué. Checkpoint **après** persistance complète, clé source+ID (+type ressource/version), déduplication au rejeu ; fenêtre figée et curseur conservé tel quel. Fiscal : lots par société, reprise inclusive avec ID pour départager, rescan borné TVA ; clés composites proposées non garanties par le fournisseur. Ni liste vide ni disparition ne supprime automatiquement un dossier. Fraîcheur inconnue si timestamp source absent ; heure locale séparée.
